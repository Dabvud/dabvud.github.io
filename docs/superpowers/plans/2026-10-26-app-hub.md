# App-Hub „Dabvud“ Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Statische Startseite unter `https://dabvud.github.io/`, die Kacheln für Dabvuds Apps zeigt (zum Start: Impostor).

**Architecture:** Eine `index.html` mit einem Array `APPS`, aus dem ein Inline-Script die Kacheln erzeugt, dazu `style.css` mit Farb-Tokens für Hell und Dunkel. Kein Build. GitHub Pages veröffentlicht direkt aus `main` (Root). Ein abhängigkeitsfreies Node-Prüfskript sichert die App-Liste ab.

**Tech Stack:** HTML, CSS, Vanilla-JS, Node (nur für `tests/check.mjs`, ohne npm-Pakete), GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-10-26-app-hub-design.md`

## Global Constraints

- Keine npm-Abhängigkeiten, kein Build, keine GitHub Actions. Pages läuft aus `main`, Ordner `/`.
- Keine externen Fonts, Scripts oder Stylesheets. System-Schriftstack.
- `lang="de"`, `<title>Dabvud – Apps</title>`, Viewport-Meta, `meta description`, `theme-color` für Hell und Dunkel.
- Kopf: Überschrift „Dabvud“, Unterzeile „Meine Apps“.
- Felder eines `APPS`-Eintrags sind genau `name`, `text`, `icon`, `link`, `art`.
- Impostor-Eintrag: `name: "Impostor"`, `text: "Partyspiel mit Fußballern – ein Handy, reihum."`, `icon: "icons/impostor.png"`, `link: "/impostor/"`, `art: "Web-App"`.
- Kachel-Hinweis: `<art> · öffnen`. Die ganze Kachel ist ein `<a>`, das im selben Tab öffnet (kein `target`).
- Raster: 1 Spalte, ab 640 px 2, ab 960 px 3. Maximalbreite 960 px, Seitenrand 16 px, kein horizontales Scrollen.
- Fußzeile mit Link auf `https://github.com/Dabvud`.
- Das Impostor-Repo (`C:\Users\trill\Desktop\Impostor`) wird nicht verändert.
- Push und Anlegen des GitHub-Repos erst nach ausdrücklichem OK des Nutzers.

## Review Focus

1. **Langer Name oder Text in einer Kachel** → bricht um (`overflow-wrap: anywhere`), sprengt das Raster nicht und erzeugt bei 375 px kein horizontales Scrollen. *(Task 2, Schritt 3, Punkt d)*
2. **Icon-Datei fehlt oder Pfad falsch** → wird vom Prüfskript gemeldet, bevor es live geht. *(Task 1, Test `icon existiert`)*
3. **JavaScript aus oder Script-Fehler** → die Impostor-Kachel bleibt über `<noscript>` erreichbar. *(Task 1, Test `noscript-Fallback`)*
4. **Unvollständiger oder falsch geschriebener `APPS`-Eintrag** (Feld fehlt, Zusatzfeld, leerer String) → das Prüfskript schlägt fehl. *(Task 1, Test `Felder`)*
5. **Tastaturbedienung** → die Kachel ist per Tab erreichbar, der Fokusrahmen ist in Hell und Dunkel sichtbar, Enter öffnet sie. *(Task 2, Schritt 3, Punkt e)*

### Task 1: Seite mit App-Liste und Prüfskript

**Files:**
- Create: `tests/check.mjs`
- Create: `index.html`
- Create: `icons/impostor.png` (Kopie von `C:\Users\trill\Desktop\Impostor\public\pwa-192x192.png`)
- Create: `favicon.svg`
- Create: `.nojekyll` (leer)
- Create: `.gitattributes` mit `* text=auto eol=lf` und `*.png binary`

**Interfaces:**
- Produces: In `index.html` steht genau ein Ausdruck `const APPS = [ ... ];` innerhalb von `<script>`. Die Kacheln landen in `<main id="apps" class="apps">`. Jede Kachel ist `<a class="app" href="…">` mit `<img class="app-icon" alt="" width="64" height="64">`, `<h2 class="app-name">`, `<p class="app-text">` und `<p class="app-meta">`. Die Klassen nutzt Task 2.
- Produces: `node tests/check.mjs` mit Exit 0 bei Erfolg und Exit 1 mit Meldungen bei Fehlern.

- [ ] **Step 1: Prüfskript `tests/check.mjs` schreiben**

Das Skript liest `index.html`, schneidet per Regex `/const APPS = (\[[\s\S]*?\]);/` das Array heraus und wertet es mit `new Function("return " + match)()` aus. Danach prüft es Folgendes und gibt jeden Fehler als eigene Zeile aus:

- `APPS ist ein nicht-leeres Array`
- `Felder`: Jeder Eintrag hat genau die Schlüssel `name,text,icon,link,art` (sortiert verglichen), und alle Werte sind nicht-leere Strings.
- `Namen eindeutig`
- `icon existiert`: `fs.existsSync(path.join(root, eintrag.icon))`
- `link`: beginnt mit `/` oder `https://`
- `Impostor-Eintrag`: Es gibt einen Eintrag, der genau den Werten aus den Global Constraints entspricht.
- `noscript-Fallback`: `index.html` enthält einen `<noscript>`-Block, in dem `href="/impostor/"` vorkommt.
- `Meta`: `lang="de"`, `<title>Dabvud – Apps</title>`, `name="viewport"`, `name="description"` und zwei `name="theme-color"` sind vorhanden. Kein `<script src=` und kein `<link` auf `http`.

Das Root ist `path.dirname(fileURLToPath(import.meta.url)) + "/.."`.

- [ ] **Step 2: Prüfung laufen lassen, sie muss fehlschlagen**

Run: `node tests/check.mjs`
Expected: Exit 1, weil `index.html` fehlt.

- [ ] **Step 3: `index.html`, Icon, Favicon, `.nojekyll` und `.gitattributes` anlegen**

`index.html` enthält: Head nach den Global Constraints mit `<link rel="icon" href="favicon.svg">` und `<link rel="stylesheet" href="style.css">`. Dann `<header>` mit `<h1>Dabvud</h1><p>Meine Apps</p>`, `<main id="apps" class="apps">` mit dem `<noscript>`-Block (statische Impostor-Kachel im gleichen Markup wie oben), und einen `<footer>` mit dem GitHub-Link. Am Ende ein Inline-Script mit `APPS` und einer Funktion `renderApps(apps)`. Die Funktion baut die Kacheln mit `document.createElement` und `textContent`, nicht mit `innerHTML`, und hängt sie an `#apps`.

`favicon.svg` ist ein „D“-Monogramm: ein abgerundetes Quadrat in der Akzentfarbe aus Task 2 (`#3b5bdb`) mit einem weißen „D“.

`style.css` existiert in diesem Task noch nicht. Die Seite darf ungestylt sein.

- [ ] **Step 4: Prüfung laufen lassen, sie muss bestehen**

Run: `node tests/check.mjs`
Expected: Exit 0, Ausgabe `OK`.

- [ ] **Step 5: Gegenprobe**

Benenne `icons/impostor.png` kurz um und führe `node tests/check.mjs` aus. Erwartet wird Exit 1 mit einer Meldung, die `icon existiert` enthält. Danach den Namen zurücksetzen.

- [ ] **Step 6: Commit**

```bash
git add .gitattributes .nojekyll index.html favicon.svg icons/impostor.png tests/check.mjs
git commit -m "feat: Hub-Seite mit App-Liste und Prüfskript"
```

### Task 2: Gestaltung und Browser-Prüfung

**Files:**
- Create: `style.css`
- Create: `README.md`

**Interfaces:**
- Consumes: Klassen und Struktur aus Task 1 (`.apps`, `.app`, `.app-icon`, `.app-name`, `.app-text`, `.app-meta`, `header`, `footer`).

- [ ] **Step 1: `style.css` schreiben**

- Tokens auf `:root`: `--bg`, `--surface`, `--text`, `--muted`, `--border`, `--accent` (hell `#3b5bdb`). Dazu ein `@media (prefers-color-scheme: dark)` mit dunklen Werten (`--accent` dort `#748ffc`). `color-scheme: light dark`.
- `body` mit `background: var(--bg)`, System-Schriftstack und `margin: 0`. Inhalts-Container mit `max-width: 960px`, `margin-inline: auto` und `padding-inline: 16px`.
- `.apps` als Grid mit `grid-template-columns: 1fr`, ab `min-width: 640px` `repeat(2, 1fr)`, ab `960px` `repeat(3, 1fr)`, `gap: 16px`.
- `.app` als Karte (Fläche, Rahmen, Radius ca. 16 px, Icon links und Text rechts) mit `min-width: 0`. Hover hebt leicht an bzw. färbt den Rahmen im Akzent. `:focus-visible` zeigt einen `outline` von 3 px im Akzent mit Abstand.
- `.app-icon` mit 64 px und Radius 14 px. `.app-name` und `.app-text` mit `overflow-wrap: anywhere`. `.app-meta` dezent in `--muted`.

- [ ] **Step 2: `README.md` schreiben**

Kurz erklären, was das ist (Startseite unter `https://dabvud.github.io/`), und den Ablauf „Neue App hinzufügen“ aus der Spec (Icon nach `icons/`, Eintrag in `APPS`, `node tests/check.mjs`, pushen) aufnehmen. Dazu der Hinweis, dass Apps aus eigenen Repos unter `/<repo>/` erreichbar sind.

- [ ] **Step 3: Im Browser prüfen**

`index.html` lokal über einen statischen Server öffnen (`npx --yes serve -l 4173 .` oder `python -m http.server 4173`) und dann prüfen:
- a) Die Kachel zeigt Icon, „Impostor“, den Text und „Web-App · öffnen“.
- b) Bei 375 px Breite gibt es eine Spalte und kein horizontales Scrollen (`document.documentElement.scrollWidth <= innerWidth`).
- c) Hell und Dunkel sind beide lesbar (Darstellung über DevTools emulieren).
- d) Temporär einen zweiten `APPS`-Eintrag mit 80 Zeichen Name ohne Leerzeichen und 300 Zeichen Text einfügen. Bei 375 px und 1280 px darf nichts überlaufen. Danach den Eintrag wieder entfernen.
- e) Tab fokussiert die Kachel mit sichtbarem Rahmen (hell und dunkel), Enter navigiert zu `/impostor/` (lokal ist ein 404 erwartet).
- f) Mit deaktiviertem JavaScript ist die Impostor-Kachel aus `<noscript>` sichtbar und gestylt.

Danach `node tests/check.mjs` ausführen, erwartet wird `OK`. Außerdem einmalig `npx --yes html-validate index.html` ausführen, erwartet wird keine Fehlermeldung. Das Paket wird dabei nicht ins Repo installiert.

- [ ] **Step 4: Commit**

```bash
git add style.css README.md
git commit -m "feat: Gestaltung des Hubs und README"
```
